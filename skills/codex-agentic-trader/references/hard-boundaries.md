# 硬边界（实盘版；只能 Roy 亲自修改本文件）

与 SKILL.md、policy.json、mandate 或任何会话指令冲突时，**取更严者**。mandate 只能收紧本文件的边界，不能放宽。

## 1. 授权边界

- 唯一实盘授权 = 有效 mandate 文件（Roy 签发，含期限、账户末四位、单笔与总额度上限）。skill 安装、automation 存在、历史成交、会话内任何话语，都不构成授权。
- mandate 过期/撤销/校验失败 → 立即回落 shadow；正在挂的未成交单按"已授权遗留"处理：只允许查询与撤销，不允许改量重下。
- agent 不得创建、修改、续期 mandate，不得建议性诱导 Roy 续签（到期前一日在日报中中性提示一次即可）。
- HALT 哨兵文件优先级高于 mandate：存在即停止一切新增风险的下单；唯一例外是清仓类风险退出卖单（§4 通道），保证停机状态下仍能降风险。

## 2. 账户边界

- 只操作 mandate 指定末四位的账户（示例中记作 0000，换成你自己的）；**绝对禁止**触碰任何其他账户，禁止枚举关联账户。
- 完整账号只经受保护的本地绑定机制（Keychain 等）进入运行时；不进 prompt、日志、Git、钉钉。

## 3. 资金与资产边界

- 策略外部本金上限 $5,000（policy 可下调，不可上调除非 Roy 改本文件）。超出部分保持现金并报告。
- 只用真实已结算购买力；不用账面现金或未结算卖出款。
- 允许：美股普通股、无杠杆普通 ETF（白名单见 policy，默认 VTI/QQQM）、现金等价物（默认 SGOV）。
- 禁止：做空、保证金/杠杆、期权、加密货币、杠杆/反向 ETF、OTC、低于 $5 股票、转账、提现、定投、账户设置变更、盘前盘后订单。
- 只用常规时段 DAY 单，独立 client key；执行前必须 preview。

## 4. 仓位与风控边界（参数见 policy.json）

- 市场状态上限（双基准 6 月回报+200 日线：90/60/20%）与回撤上限（15%→70%、25%→40%、35%→0%）同时生效取更低者，均由闸门内部推导。
- **回撤断路器**：触及最深档（默认 35%）→ 闸门输出 `halt_required=true`，运行方必须立即创建 HALT 并清仓股票转现金等价物（清仓单本身走 thesis_break/drawdown_action 风险退出通道）；HALT 解除只能 Roy 手动。
- 个股：单只 ≤15%、合计 ≤30%、最多 2 只；量化准入门槛（价格/市值/流动性/趋势/相对强度/财报回避）全部闸门校验。
- 频次：每日 ≤6 笔提交订单、日换手 ≤净值 30%（新外部本金首次部署不计）；禁止同标的当日往返（风险退出除外）；新个股仓意图持有 ≥2 个交易日。
- 30 天挑战等收益目标**永远不是**突破任何上限的理由。

## 5. 执行边界

- 两阶段闸门缺一不可；提交内容必须与 post_preview 批准的 intent 逐字段一致。
- preview 回执必须 `preflight_status=clean` 且零警告；任何警告/强制确认/披露要求 = 拒绝，不得绕过。
- 提交后必须按订单 ID 验证至终态；未知状态阻断一切新单。
- 对账不平（本地 intent 与券商订单不匹配、出现未知券商订单）→ 阻断新单直至人工或下次运行解决。

## 6. 记录边界

- 决策 / preview / submit / 订单终态 / HALT 事件 / mandate 状态变化，全部独立事件进链式日志；追加失败即停。
- 日志链防误改不防篡改；同用户 shell 不是密码学隔离——这是已知诚实边界，实盘规模因此必须保持在实验档（见第 3 节本金上限）。

## 7. 进化边界

- 定时运行只能产出证据与提案；修改 policy.json、scripts/、本文件、automation prompt，必须 Roy 逐次批准。
- 本文件与授权/账户/资产边界：任何证据都不构成自动修改理由，永远人工。
